# CS-320: Software Testing, Automation, and Quality Assurance
## Portfolio Reflection

### How can I ensure that my code, program, or software is functional and secure?

I can ensure that my code is functional by developing and executing thorough unit tests based on the requirements of the software. Testing individual components helps identify errors early and confirms that each part of the program behaves as expected. I can also use boundary-value testing, positive and negative test cases, and requirements-based testing to make sure that the software handles both normal and unexpected input correctly.

Security should also be considered throughout the development process rather than being treated as something added at the end. I can improve software security by validating user input, preventing invalid or unexpected data from being accepted, protecting sensitive information, and following secure coding practices. Automated testing can help identify potential problems before software is released, while code reviews and repeated testing can help maintain quality as the program changes.

### How do I interpret user needs and incorporate them into a program?

I interpret user needs by carefully examining the requirements and identifying what the software must do, what information it needs to accept, and what restrictions apply to that information. Requirements provide a foundation for determining the expected behavior of the program and for creating meaningful test cases.

I incorporate those needs into a program by translating each requirement into specific functionality and then testing that functionality against the original requirement. This helps ensure that I am solving the actual problem rather than simply creating software that works according to my own assumptions. When requirements are unclear, I would seek clarification before making design decisions because an incorrect assumption early in development can lead to unnecessary rework later.

### How do I approach designing software?

I approach software design by first understanding the requirements and breaking the problem into smaller, manageable components. I consider the responsibilities of each class or component, how those components interact, and how the design can remain maintainable as the software grows.

The projects in this course reinforced the importance of designing with testing in mind. A well-designed system should have components with clear responsibilities so that they can be tested independently. I also try to avoid unnecessary complexity and focus on creating a design that is readable, maintainable, and consistent with the requirements.

Overall, my approach to software development is to begin with the requirements, design around those requirements, implement the smallest appropriate solution, and then use testing to verify that the implementation behaves correctly. This process creates software that is not only functional, but also easier to maintain, evaluate, and improve over time.
